# build-resume: базовое резюме под семейство ролей

Рабочая директория — корень репозитория. Результат: `resumes/<family>_<ru|en>.tex` + PDF.

Базовое резюме — заготовка «по умолчанию» для семейства ролей, а не финальный отклик.
Отклик под конкретную вакансию собирает `tailor-cv`, копируя базу в `applications/`.
База при этом не меняется.

Предусловие: `facts.md` и `profile.json` заполнены (иначе — `init-cv`).

## Воркфлоу

### Шаг 1 — Вход
- Семейство ролей — из аргумента или из `profile.json` → `role_families[]`.
  Если аргумента нет и семейств несколько — спросить, какое.
- Язык: `ru`, `en` или оба. По умолчанию — под `defaults.primary_market`.
- Рынок → комплект контактов из `profile.json` → `contacts.<market>`.

### Шаг 2 — Отбор фактов
Прочитать `facts.md` целиком. Отобрать всё с тегом семейства:

- `TITLE-*` — заголовок;
- `SUM-*` — блок «О себе» на нужном языке;
- `EXP-*` — весь релевантный опыт (опыт не выбрасывается, даже если слабо релевантен:
  дыры в датах читаются хуже, чем нерелевантная строка; но буллеты можно сократить);
- `PRJ-*` — проекты, `[verified]` выше `[basic]`;
- `SKL-*` — группы навыков; **только `[verified]` и `[basic]`**;
- `EDU-*`, `AWD-*`, `RES-*` — по релевантности.

Проверить перед сборкой: каждый навык из «Навыков» подсвечивается хотя бы одним
буллетом в «Опыте» или «Проектах». Не подсвечивается — либо убрать навык, либо
добавить подтверждающий буллет (если для него есть факт).

### Шаг 3 — Сборка
- Скопировать `templates/base_<ru|en>.tex` → `resumes/<family>_<ru|en>.tex`.
- Заполнить блок `\newcommand{\CVName}` / `\CVTitle` / `\CVEmail` / `\CVPhone` /
  `\CVTelegram` из `profile.json`.
- Наполнить секции. **Каждый содержательный блок — с `% FACT: <id>`.**
- Порядок внутри секций: сильное и релевантное выше. Верхняя треть первой страницы —
  самая весомая и для человека, и для ранжирования.
- Бюджет — `defaults.page_budget` страниц. Порядок сокращения:
  1) «Достижения» до 3 строк → 2) самые слабые `[basic]`-проекты → 3) «О себе» до
  2–3 предложений. Контакты, опыт и образование не трогать.
- Секции без содержимого удалять целиком, а не оставлять пустыми.

### Шаг 4 — Компиляция
```bash
cd resumes && pdflatex -interaction=nonstopmode -halt-on-error <family>_<lang>.tex \
  && pdflatex -interaction=nonstopmode -halt-on-error <family>_<lang>.tex \
  && rm -f *.aux *.log *.out
```
Ошибка компиляции — читать `.log`, чинить исходник. Частые причины: незаэкранированные
`%`, `&`, `_`, `#` в тексте и кириллица в EN-шаблоне (там нет T2A).

### Шаг 5 — Проверка
```bash
python3 .claude/skills/tailor-cv/scripts/ats_check.py \
  --pdf resumes/<family>_<lang>.pdf --tex resumes/<family>_<lang>.tex \
  --market <рынок>
```
Без `--keywords`: у базового резюме нет вакансии, проверяются извлечение текста,
имя, контакты, blacklist и провенанс. Требуется `RESULT: PASS`.

Дополнительно посмотреть глазами: `pdftotext resumes/<family>_<lang>.pdf -` —
текст должен читаться в правильном порядке.

### Шаг 6 — Итог
Сказать: какие факты вошли, какие остались за бортом и почему, сколько страниц,
результат проверки. Если фактуры на семейство ролей объективно мало — сказать прямо,
с указанием, каких блоков не хватает.

## Правила

- Ничего сверх `facts.md`. Нужен новый факт — сначала в банк, потом в резюме.
- `[gap]`-термины в резюме не попадают никогда.
- Комплекты контактов не смешиваются.
- Формат намеренно простой: одна колонка, без таблиц, колонок, иконок и фото —
  подробности в `../tailor-cv/references/ats-guide.md`.
