# tailor-cv: сборка отклика под вакансию

Рабочая директория — корень репозитория (там, где `profile.json` и `facts.md`).
Пути ниже — от корня. Скилл: `.claude/skills/tailor-cv/`.

Предусловие: `facts.md` и `profile.json` заполнены. Если нет — сначала `init-cv`.
Если под нужное семейство ролей нет базового резюме в `resumes/` — сначала `build-resume`.

## Железные правила (нарушать нельзя)

1. **Только факты из `facts.md`.** Ни одного утверждения сверх банка. Каждая
   содержательная строка резюме несёт комментарий `% FACT: <id>`.
2. **`[gap]`-темы никогда не идут в резюме** (список — `gap-blacklist.txt`). Их место —
   в сопроводительном, в формулировке «руками не трогал, готов быстро освоить —
   есть <реальный смежный опыт>».
3. **Контакты по рынку, не смешивать.** Комплект берётся из `profile.json` →
   `contacts.<market>` целиком.
4. **Без инфляции сеньорности.** Уровень зафиксирован в `facts.md` §9.
5. **Ключевое слово вакансии зеркалится, только если за ним стоит реальный факт.**
   Никакого стаффинга и скрытого текста — AI-скрининг детектирует это как фрод.
6. **Честность формулировок:** `[basic]`-факты — с оговорками («учебно», «базово»);
   границы из предупреждений `facts.md` (формат занятости, командные результаты, NDA)
   соблюдаются буквально.

## Воркфлоу

### Шаг 1 — Интейк вакансии
- Дан URL → получить страницу через WebFetch. Если сайт блокирует или отдаёт заглушку →
  браузерные MCP-инструменты. Если и это недоступно — попросить вставить текст.
- Создать папку отклика: `applications/<YYYY-MM-DD>_<компания>_<роль-слаг>/`.
- Сохранить `vacancy.md`: URL, дату получения, полный текст вакансии без сокращений
  (вакансии удаляют — это единственная копия).

### Шаг 2 — Анализ вакансии → `analysis.md` + `keywords.tsv`
Прочитать `profile.json` (семейства ролей и рынки) и зафиксировать в `analysis.md`:

- **Семейство роли** — одно из `role_families[].id`; выбирать по `signals` и тексту
  вакансии. Вакансия на стыке — выбрать доминирующее, отметить второе. Совсем
  неоднозначно — задать пользователю ОДИН уточняющий вопрос.
- **Рынок** — ключ из `contacts`: РФ-работодатель / hh.ru-URL / русскоязычная вакансия
  → `rf`; иначе `intl` (по умолчанию — `defaults.primary_market`).
- **Язык отклика** — по рынку и языку вакансии.
- **Ключевые слова** → `keywords.tsv`, формат `must<TAB>термин` / `nice<TAB>термин`,
  15–25 штук. `must` — из требований, `nice` — из «будет плюсом». Сохранять ТОЧНЫЕ
  словоформы вакансии, включая обе языковые версии, если текст смешанный.
- **`[gap]`-требования вакансии** — сверить с `gap-blacklist.txt` и `facts.md` §7/§9;
  это список для сопроводительного письма.

### Шаг 3 — Отбор фактов
Прочитать `facts.md` ЦЕЛИКОМ. Отобрать факты по тегу семейства:
- `[verified]` — в приоритете, ими закрывать must-требования;
- `[basic]` — включать с честными формулировками, если релевантны;
- построить в `analysis.md` карту «требование вакансии → факт-ID»: что закрыто, что нет.

Карта — главный артефакт шага: она же основа сопроводительного и подготовки к собесу.

### Шаг 4 — Сборка резюме
- Скопировать базу `resumes/<семейство>_<ru|en>.tex` → `resume.tex` в папку отклика.
  Провенанс-комментарии уже внутри — сохранять и обновлять при правках.
- **Заголовок** — из `TITLE-*`, максимально близко к названию вакансии (для hh это
  самый весомый фактор ранжирования).
- **Переупорядочить**: релевантные буллеты и проекты — выше; нерелевантные проекты
  убрать. Бюджет — `defaults.page_budget` страниц.
- **Зеркалирование**: переформулировать буллеты под точную терминологию вакансии там,
  где факт это позволяет. Для международных — расшифровка аббревиатуры один раз.
- **Размещение ключевых слов**: заголовок, «О себе», «Навыки», первые буллеты опыта
  (верхняя треть — самая весомая).
- Каждая изменённая строка — с актуальным `% FACT:`.
- Контакты в блоке `\newcommand{\CVEmail}` / `\CVPhone` — под рынок из шага 2.

### Шаг 5 — Компиляция
```bash
cd <папка отклика> && pdflatex -interaction=nonstopmode -halt-on-error resume.tex \
  && pdflatex -interaction=nonstopmode -halt-on-error resume.tex \
  && rm -f *.aux *.log *.out
```

### Шаг 6 — ATS-проверка
```bash
python3 <корень>/.claude/skills/tailor-cv/scripts/ats_check.py \
  --pdf resume.pdf --tex resume.tex --keywords keywords.tsv --market <рынок> \
  > ats-report.md; cat ats-report.md
```
Корень репозитория скрипт находит сам (вверх по дереву до `profile.json`).

- `RESULT: FAIL` → исправить и повторить шаги 4–6.
- Непокрытый must-термин, за которым ЕСТЬ реальный факт → вписать термин, пересобрать
  (максимум 2 итерации). Факта НЕТ → оставить непокрытым и отметить в сопроводительном.

### Шаг 7 — Сопроводительное письмо → `cover_letter.md`
200–300 слов, язык отклика. Структура:
1. Зацепка: почему эта компания/продукт — 1–2 предложения с конкретикой из вакансии.
   Без общих слов про «динамично развивающуюся команду».
2. 2–3 сильнейших совпадения «требование → мой опыт» (по карте из шага 3).
3. Если у вакансии есть `[gap]`-требования — обязательный честный абзац:
   «<X> руками не трогал — готов быстро освоить: есть <смежный реальный опыт>».
   Замалчивать пробел хуже, чем назвать его самому.
4. Короткое закрытие с готовностью к тестовому/собеседованию.

### Шаг 8 — Блоки для профиля hh.ru (только рынок `rf`) → `hh_profile.md`
Скрининг hh идёт по полям профиля, а не по PDF (см. `references/ats-guide.md` §1):
- **Заголовок** — точное название роли, как в целевых вакансиях.
- **Ключевые навыки** — теги по одному в строке (только `verified`/`basic`),
  продублировать точные термины из требований вакансии.
- **О себе** — адаптированный `SUM-*` в plain text, без LaTeX.
- **Опыт** — буллеты карточек в plain text, для копипасты в поля.

### Шаг 9 — Лог
Добавить строку в `applications/APPLICATIONS.md`, статус `подготовлено`.

### Шаг 10 — Итог пользователю
Кратко: семейство и база, что подчёркнуто, покрытие must-слов (N из M), какие
`[gap]` ушли в сопроводительное, путь к папке. Напомнить, что отклик отправляется
руками, а для Workday — проверить автозаполнение полей после загрузки PDF.

Если в ходе работы всплыл факт, которого нет в банке, — не вписывать его в резюме
молча: сначала спросить человека и записать в `facts.md`, потом использовать.

## Справочники

- `references/ats-guide.md` — механика hh.ru, РФ и международных ATS, правила
  ключевых слов, ловушки LaTeX. Читать при каждом запуске.
- `../../../gap-blacklist.txt` — запрещённые в резюме термины. Держать в синхроне
  с `[gap]` в `facts.md`.
