# CV-Tailor

Репозиторий-заготовка: система резюме, которая собирается из **единого банка фактов**
и тейлорится под конкретную вакансию с автоматической ATS-проверкой.

Ничего личного внутри нет — репозиторий пустой каркас. Свои данные вы (или агент)
кладёте в `profile.json` и `facts.md`. В `example/` лежит полностью заполненный
пример с вымышленным человеком — чтобы видеть, как выглядит результат.

## Зачем

- **Версии не расходятся.** Факт правится один раз в `facts.md` и переносится в резюме.
  На собеседовании ничего не «поедет».
- **Нельзя приукрасить незаметно.** Каждая содержательная строка резюме помечена
  `% FACT: <id>`; скрипт проверки падает, если в резюме появилось что-то сверх банка.
- **Отклик собирается за один заход.** Даёте агенту вакансию — получаете папку с резюме,
  PDF, ATS-отчётом, сопроводительным письмом и блоками под поля профиля hh.ru.

## Быстрый старт

```bash
git clone <этот-репозиторий> my-cv && cd my-cv
rm -rf .git && git init          # своя история, без истории заготовки
```

Дальше — в Claude Code из корня репозитория:

```
/init-cv
```

Скилл прочитает всё, что вы положите в `inbox/` (старые резюме, выгрузку hh/LinkedIn),
проведёт интервью по пробелам и заполнит `profile.json`, `facts.md`, `gap-blacklist.txt`,
после чего соберёт базовые резюме под ваши роли.

Дальше на каждую вакансию:

```
/tailor-cv <URL вакансии или вставленный текст>
```

## Структура

```
.
├── profile.json          ← личность, контакты по рынкам, семейства ролей (ЗАПОЛНИТЬ)
├── facts.md              ← БАНК ФАКТОВ: единый источник правды (ЗАПОЛНИТЬ)
├── gap-blacklist.txt     ← термины, которых нет в опыте: в резюме запрещены (ЗАПОЛНИТЬ)
├── CLAUDE.md             ← правила для агента: честность, провенанс, контакты
├── templates/
│   ├── base_ru.tex       ← скелет резюме RU (кириллица + ToUnicode для парсеров)
│   └── base_en.tex       ← скелет резюме EN
├── resumes/              ← базовые резюме под каждое семейство ролей (+ PDF)
├── applications/         ← отклики под конкретные вакансии + лог APPLICATIONS.md
├── inbox/                ← сюда положить старые CV для init-cv (в git не попадает)
├── example/              ← полностью заполненный пример (вымышленный человек)
└── .claude/skills/
    ├── init-cv/          ← собрать банк фактов с нуля: источники + интервью
    ├── build-resume/     ← собрать базовое резюме под семейство ролей
    └── tailor-cv/        ← собрать отклик под конкретную вакансию + ATS-проверка
```

## Три скилла

| Скилл | Когда | Что делает |
|---|---|---|
| `init-cv` | один раз, на старте | Источники + интервью → `profile.json`, `facts.md`, `gap-blacklist.txt` |
| `build-resume` | при появлении новой целевой роли | Факты по тегу роли → `resumes/<роль>_<ru\|en>.tex` + PDF |
| `tailor-cv` | на каждую вакансию | Разбор JD → резюме → PDF → ATS-отчёт → сопроводительное → лог |

## Правило честности

Каждый факт в банке помечен уровнем:

- `[verified]` — делалось руками, можно защищать на собеседовании;
- `[basic]` — есть, но поверхностно (учебный курс, разовая задача) — формулировать честно;
- `[gap]` — нет опыта. **В резюме как навык не пишется никогда.** Место таких тем — в
  сопроводительном письме, в честной рамке «руками не трогал, готов быстро освоить —
  есть <смежный реальный опыт>».

`[gap]`-термины дублируются в `gap-blacklist.txt`, и `ats_check.py` роняет проверку,
если они просочились в текст резюме.

Отдельно запрещены накрутки под ATS: белый текст, скрытые ключевые слова, стаффинг.
Современные парсеры и AI-скрининг это детектируют и помечают как фрод — подробности
в `.claude/skills/tailor-cv/references/ats-guide.md`.

## profile.json — схема

| Поле | Смысл |
|---|---|
| `identity.name.{ru,en}` | Имя в двух написаниях; `ats_check` проверяет наличие в PDF |
| `identity.telegram`, `identity.links` | Контактные строки для шапки резюме |
| `identity.location` | Город, готовность к переезду/удалёнке (для сопроводительных) |
| `contacts.<market>` | Комплект email + телефон под рынок. **Комплекты не смешивать** |
| `role_families[]` | Семейства ролей: `id`, подписи, `signals` — по ним `tailor-cv` относит вакансию |
| `defaults.page_budget` | Бюджет страниц резюме (обычно 2) |
| `defaults.primary_market` | Рынок по умолчанию |

Рынки (`rf`, `intl`, …) — произвольные ключи. Смысл разделения: на разные рынки уходят
разные контакты, и `ats_check` не даст перепутать (частая и дорогая ошибка — на
международный отклик уходит резюме с российским номером или наоборот).

## Ручные операции

```bash
# собрать PDF
cd resumes && pdflatex -interaction=nonstopmode base_ru.tex && rm -f *.aux *.log *.out

# ATS-проверка (корень находится автоматически по profile.json вверх по дереву)
python3 .claude/skills/tailor-cv/scripts/ats_check.py \
    --pdf applications/<папка>/resume.pdf \
    --tex applications/<папка>/resume.tex \
    --keywords applications/<папка>/keywords.tsv \
    --market rf
```

Нужен `pdflatex` (TeX Live / MacTeX) и `pdftotext` (poppler) либо `pypdf`.
